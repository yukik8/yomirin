# 目の実験室 (#6)

ノートPCのカメラで、**目が画面にあるか・うとうとしているか・ページのどこを読んでいるか**が、どこまで取れるかを、拡張に入れる前に測る。拡張には入れない(目の本体は #7、ページの中の読み進みは #8)。

- 映像はこのページの中で数字にするだけで、保存も送信もしない。書き出すのは数字の CSV だけ
- MediaPipe Face Landmarker(`@mediapipe/tasks-vision` 1.2.3)をネットから読む。JS と WASM は jsDelivr、顔のモデルは Google の置き場から。WASM が 14MB、モデルが 3.7MB ある。#7 で拡張に同梱すると、拡張が 18MB ほど増える
- 計算は `signals.js`(カメラにも画面にも触らない。#7 がそのまま拡張へ移す)、本文の組み方は `layout.js`、画面は `lab.js`。テストは `tests/extension/eyes.test.mjs`
- 本文は青空文庫の3作(`books.json`。章の絵巻の試写室と同じもの)

## 開く

リポジトリの一番上で:

```sh
python3 -m http.server 8000
```

http://localhost:8000/tools/eyes-lab/ を開き、「カメラを始める」。はじめはモデルの読み込みに数秒かかる。

- **めくる:** スペース・→(縦書きは ←)・ページをクリック。**戻る:** ←(縦書きは →)
- **ラベル:** 1 上の行 / 2 下の行 / 3 左ページ / 4 右ページ / 5 画面の外 / 6 眠いふり / 7 あくび。押すと付き、もう一度押すと外れる(0 でも外れる)
- **E:** 推定の帯を出す/消す。**G:** なぞる
- 右の欄: カメラの絵(目尻・目頭・まぶた・虹彩の点。閉じると虹彩の点が赤くなる)、いまの数字、判定(#6 の基準に照らして ○×)、設定

## ページのどこを読んでいるか(#8 の自己較正)

二つの手がかりを合わせて追う。

- **時間:** めくった直後はページの頭にいて、ふだんの速さ(教師にしたページの時間から)で進む。画面から外れている間は止まる
- **目:** 較正の儀式(画面の点を順に見る)はしない。めくった直後はページの頭、めくる直前は終わりにいて、その間は同じ速さで読んだとみなし(時間の教師)、目の数字 → 読み進み 0〜1 をリッジ回帰で当てはめる。めくるたびに当てはめ直す。まばたき中のコマ(まぶたの開きがふだんの半分未満)は使わない
- **合わせ方:** 位置と速さを追うカルマンフィルタ(`createFollower`)。時間で進めながら、目の推定が来るたびに位置と速さを直す。目の誤差は数秒続く(頭が少し動くと、しばらく同じ向きにずれる)ので、2.5秒ぶんのコマを1コマぶんの証拠として数える(`EYES.follow`)

紙面の帯は合わせた推定で、**濃い行が真ん中、薄い行が確からしさ(±1σ)の幅**。ノートPCのカメラで1行は当てられない(#6 の「精度の見込み」)ので、幅で見せる。4ページ読むと出る。目の当てはめが合っていないあいだ(門が閉じている。直近3ページで、めくる直前の推定が 0.7 を超えたのが2ページ未満)は枠だけ。

- 教師にしないページ: カメラを始めたときのページ・戻った/読み直したページ・3秒未満か10分超・2秒以上画面から外れたページ・なぞったページ
- 目の数字は3組を並べて比べる: **eyes**(既定)は目だけ(両目の虹彩の位置 x・y、blendshape の視線 下・上・内・外、まぶたの開き の14)、**base** は #8 に書いた6つ(虹彩の位置+頭の yaw・pitch)、**plus** は eyes + 頭の向き。最初の記録(2026-11-27)では、頭の向きと読み進みの相関がページごとに符号まで入れ替わり、目の数字は全ページでそろっていた
- 当たっているかは2通りで見る
  - **ページを抜いて当てる(目だけ):** そのページを除いて当てはめた式で、そのページを当てる。正解は時間の教師(同じ速さで読んだとみなした位置)なので、時間を使う推定はここでは比べない(有利すぎる)
  - **なぞり(目だけ・時間だけ・合わせた):** G でなぞるを入れると、いまの行だけが濃くなり、下線が進む。**速さはページごとに ×0.6〜1.5 で揺れ、途中で一度 2.5 秒止まる**。それを目で追ったページを当てる。正解はなぞった位置(本当の位置で、時間に比例しない)。「合わせた」が「時間だけ」より当たっていれば、目が効いている
- 判定は「ページの上1/3を読んでいるか、下1/3を読んでいるか」を、推定が 0.5 のどちら側かで見分けられた割合(真ん中の1/3は数えない)と、ずれ(平均の差。0.1 ≒ 18行のページで2行)。#6 の基準は 80%

## 測る手順(#6 の判定基準)

条件(眼鏡あり/なし・ふだんの明るさ・外付けのディスプレイ)ごとに通す。始める前に「条件」の欄に書いておく(CSV の行に残る)。

1. **向きを確かめる:** 正面を見てから下を向き、「頭」の pitch が負になるか。逆なら「pitch の向きを逆に」を入れる
2. **最初の2分はふつうに読む**(まぶたの「いつもの開き」を取る)。E で帯を消しておく(帯が見えると目で追ってしまう)
3. **10分読む。** そのあいだに20回、5 を押して画面の外(手元・横・スマホ)を見て、戻ったら 5 で外す
4. **上の行・下の行:** 1 を押して上の行を、2 を押して下の行を、それぞれ1分ほど読む(下の行を読んでうつむいたのを、うとうとと取り違えないか)
5. **眠いふり:** 6 を押して、目を半分閉じて60秒。7 を押してあくびを何回か
6. **なぞる:** G で入れて5ページ以上(下線を目で追う。速さが変わり、途中で止まる)。G で戻す
7. **解像度:** 「カメラ」を 320×240(#7 の予定)に変え、カメラを止めて始め直し、3・6 をもう一度
8. **CPU:** 読んでいるあいだに、アクティビティモニタで Chrome のヘルパー(GPU / Renderer)の CPU を見る(1コアの25%未満)
9. **書き出す:** CSV が4つ落ちる(`frames`・`seconds`・`events`・`pages`)。結果は #6 の「結果」に書く

縦書きの本を読むなら、組み方を縦書きにする(読み進みが左右の動きになるので、上下より取りやすい見込み)。見開きの左右はラベル 3・4 で見る。上1/3・下1/3 の判定は見開きにしない1ページで測る。

## 書き出すもの

| ファイル | 1行 | 中身 |
|---|---|---|
| `frames` | 1コマ | blendshape(まぶた・視線・あご)・頭の向き・虹彩の位置・まぶたの開き(ふだんとの比・まばたき中か)・顔の幅・明るさ・判定(閉じ・画面・うとうと)・推定(目だけ eyes・base・plus、時間だけ、合わせた ±σ)・なぞった位置・処理の時間・ラベル・条件 |
| `seconds` | 1秒 | #6 の信号(`rs_eyes`)の形: `t, face, on_screen, progress, closed_ms, perclos, drowsy, conf` + ページ・ラベル・条件 |
| `events` | 出来事 | めくり・戻る・ラベル・away / back・まばたき・長い閉じ・あくび・こっくり・うとうとの on / off |
| `pages` | ページ | 開いていた時間・なぞったか(速さの倍率・止まった行)・教師にしないか・画面から外れていた時間・字のある割合・字数 |

顔の点(478点)と映像は書き出さない。
