# 章の絵巻の試写室 (#51 → #34)

読み進めた話を踏まえて場面を読み取り、余白の絵が、読んだ話をアニメで演じる。

- **ページを開いた瞬間に、そのページを先に送る。** 読んでいる間に、Claude がそのページの場面と動きを用意する。答えには**封**をしておく
- **めくった瞬間に封を開け、いま読み終えたページの場面を数秒のアニメで演じる。** 読み終えた直後に、そのページの話が動く(読んだ所から遅れない)
  - 場面が移ると、絵巻が流れて次の区画へ進む(旅をしているように)
  - 物が道に沿って動く(トロッコが線路を揺れながら走る)・現れる・去る・灯りがともる・日が沈む・暗くなる
  - 演じている間は、木が揺れ、水が浮き沈みし、灯がゆらぐ
- **読んでいる間は止まっている**(style.md §0)。1ページの場面は 4.5 秒まで
- 章の終わりに、最後のページの場面を演じてから、その章の区画を順に並べた絵巻が広がり、灯りがともる。次の章では新しい絵巻(持ち越さない)
- 形と画風は #50 と同じ: Claude が書いた形のデータ(SVG の path と色の名前)に、端末の画風を掛ける(`../scene/scene.js`)

これまでに変えたこと(本人と決めた・2026-10-26〜11-04):

- 真っ白な紙に色が付いていく見せ方(#50 の段階・下描き → 色)はやめた。「その絵の物語が少しずつ動く方が好き」
- 読み終えたページだけを送ると、絵は読んだ所から遅れて追いかけることになる。そこで、まだ読んでいないページを先に送り、封で守る形にした。「まだ読んでないってことが絶対にわかるハーネスにした上で、先に送っちゃう方が良い」

判定基準と結果は #51 に書く。

- `runs/<本>.<下調べ>.<読み取り>-<描く>[.from<ページ>][.ch<章>].<回>.json` に書き、`runs/index.json` を書き直す

## 仕組み

役は4つ。区切り・送るもの・検め・封・演じ方は端末の側(`emaki.js`)が決め、`run.py` は Claude を呼んで答えを記録に書くだけ(`device.mjs` で端末の側を呼ぶ)。

| 役 | いつ | 渡すもの | 返すもの | モデル(既定) |
|---|---|---|---|---|
| 下調べ | 本ごとに一度 | 書名と著者 | 知っているか・全体のあらすじ(結末まで)・世界 | Opus |
| 読み取り | ページを開いた瞬間(1ページに1回) | 下調べ・ここまでの話・いまの場面と物と所・**いま開いたページ(まだ読んでいない)** | 出来事・場面(2つまで)・新しく出た物・形の変わった物・同じ場面での物の動き。どれにも本文の語句を付ける | Sonnet |
| 描く(アニメの演出) | 新しい区画か、描き足す物があるとき(読み取りのすぐ後) | ここまでの話・場面・物の一覧・このページの出来事(描き足しのときは、いまの絵と所と道) | 地・所・道・物ごとの形と足もと・最初の様子・灯り・揺らぎ・出来事に沿った動き | Opus |
| 章のまとめ | 章の最後のページを読み終えたとき | この章の出来事 | 200字のまとめ | 読み取りと同じ |

演出の言葉(どれも決まった語だけ。端末がアニメにする):

- **所(spots):** 物が居られる所・動いて行ける所(坂の上・茶店の前・画面の外の左など)。座標と、その所での大きさ(奥は小さく)
- **道(routes):** 所から所への曲がった道(線路のカーブなど)。物の足もとが通る線(SVG の path の d)。無ければまっすぐ動く
- **動き:** `move`(所へ)・`leave`(去る。所を書けば、そこへ動きながら消える)・`appear`(現れる)・`light`(灯る)・`dark`(消える)。速さは `slow`・`mid`・`fast`、動きながらの様子は `bob`(揺れながら・車)・`spin`(回りながら)
- **物の最初の様子:** `start`(最初に居る所)・`hidden`(最初は見えない)・`lit`(最初に灯っているか)。動く物は、いちばん大きく見える所で描かせる(奥へ動くときに縮めるだけで、ぼやけないように)
- **揺らぎ(loop):** `sway`(木・草・花)・`bob`(水)・`flicker`(灯・火)・`drift`(煙・雲)。演じている間だけ
- 新しい区画の動きは描く係が、このページの出来事の番号を付けて返す。同じ場面の続きの動きは読み取りが、本文の語句を付けて返す。新しく出た物の「現れる」と、時刻が移ったときの「日が暮れる」(色を重ねる)は、端末が足す

本ごとに端末に残すもの(本番では記録層・`chrome.storage.local`):

- 下調べ(画面に出さず、エクスポートにも入れない)
- ここまでの話: 途中から読み始めたときの前のあらすじ(`seed`)・済んだ章のまとめ・この章の出来事(封を開けたものだけ)
- いまの章の絵巻: 区画ごとに、地・所・道・物(形・足もと・いま居る所・灯り)。章が終わったら捨てる
- 封をした答え: いま開いているページのぶんだけ。めくらずに閉じた・戻った・飛んだときは、開けずに捨てる

### ネタバレの守り

1. **封(端末):** いま開いたページから作ったもの(出来事・場面・物・動き)は、そのページをめくるまで、画面にも、ここまでの話にも、次に送るものにも入れない。めくらずに閉じた・戻った・飛んだページの封は開けずに捨てる。間に合わなかった答えは、読んでいる途中では演じず、次のめくりまで待つ
   - 試写室では、回 [a, b] の答えを b をめくった後(turn = b + 1)にだけ当てる(`replay`・`timeline`)。「封の前に出たもの」を数え、0 でなければ道具のまちがい
2. **門(端末・機械で):** 出来事・場所・時刻・天気・雰囲気・物・動きの一つずつに、本文の語句を付けさせる。端末が送ったページにそのまま有るかを確かめ、無いものは捨てる。止めた語句がそれより後のページにだけ有れば「先の語句」として数える(`whereIs`)。下調べから漏れた先の話も、ここで止まる
3. **描く係は書名も下調べも知らない:** 渡すのは、ここまでの話と、門を通った場面と物と出来事だけ(`drawRequest`)。返った形は、頼んだ物の id のものだけを受け取る。動きは、門を通った出来事の番号が付いたものだけ
4. **章のまとめは下調べなしで書く:** 渡すのは、門を通った出来事だけ
5. **指示:** 読み取り係には、このページより先のことは言い換えやほのめかしも書かない・雰囲気も先取りしない、と指示する
6. **判定役(試写室だけ):** 読み終えたあと、全文を知る判定役が、回ごとに端末に残っていたものを見る

残る穴(判定役で見る): 門を通った語句に付けた説明(出来事の文・物の見た目)に先のことを混ぜる、どれを主役にするかの選び方、途中から読み始めたときの `seed`(語句で確かめられない)。

### 演じ方(`timeline`・`clipOf`・`stageAt`)

- 回 [a, b] の答えは、b をめくった瞬間(turn = b + 1)に、1つの場面として演じる
- 本文の順に並べる。新しい区画は、その中の動きより先(区画が現れてから動く)。同じ語句の動きは一緒に、ほかは順に
- 長さ: 区画が流れる 0.9 秒・動きは速さで 0.8〜2 秒・現れる/去る/灯るは 0.7 秒(slow なら倍)・日が暮れるのは 1.2 秒。合わせて 4.5 秒を超えたら縮める
- 章の最後のページの場面は、余白で演じてから絵巻を広げる

### 絵

- **舞台:** 320×240 の舞台(#50 と同じ)を、余白の大きさに縮めて置く。区画を横に並べた帯を流して、いまの区画を見せる。区画の両端は紙に溶かす
- **層:** 区画の中は、地(`groundSvg`)・物ごとの層(`thingSvg`・透明)・時刻の色を重ねる層。いちばん上に、縁を揺らしながら紙に溶かす覆い(`edgeSvg`)を置く
- **動き:** 物の層を Web Animations で動かす。道は path の上の点を拾ってたどり、所の大きさで縮める。揺れ・回る・揺らぎは中の画像に付ける。描き終えた画像を動かすだけなので、水彩のフィルタを掛け直さない
- **灯り:** 灯っていない姿と灯った姿を重ねて持ち、入れ替える。章の終わりの絵巻では全部ともす
- **章の絵巻:** 区画を順に横へ並べた1枚の SVG(`scrollSvg`。物は最後に居た所)。左から右へゆっくり流す(区画ごとに 2.2 秒)
- reduced-motion では、余白も絵巻も演じず、置き換えるだけ

## 見本

`runs/torokko.sample.json` は、Claude Code が同じ決まりで手で書いた読み取りと絵(トロッコ全文・12ページ・10区画・動き28)。元は `sample.mjs`。道具を確かめるためのもので、計測していないので判定には使わない。

作って分かったこと:

- 2ページごとに読み取ると、その間に場面が二つ過ぎることがある(トロッコの「一人で走る帰り道」と「村」)。読み取りの答えの最後の場面だけを描くと、話でいちばん大事な場面が抜ける。そこで、1回に場面を2つまで返させる(三つ以上なら、いちばん大事な場面と最後の場面)。1ページごとになっても残している
- 物は名前で指す(1回目の答えの中では、まだ id の付いていない物を指せない。1つの区画の中で名前は重ならない)
- 区画が現れるのと同じ瞬間に物が動くと、動く前の様子が見えない。区画を先に流し、中の動きはその後に回した
- 奥に描いた物を手前へ動かすと、拡大してぼやける。動く物は手前で描かせ、最初の所(`start`)を別に持たせた
- 描き足した物を、区画を最初に作ったときの層だけで組むと、出てこない(竹藪・羽織)。描き足すたびに層を足す

## 本人が回した前の形の版から分かったこと

`runs/torokko.old-format.json` は、本人の API キーで、前の形(読み終えた2ページごとに送り、描き足すだけで物が動かない)のまま回したトロッコ(2026-10-26。6回の読み取りと描くまで。章のまとめと判定役の前で止まった)。判定には入れない。

- 読み取りの語句は 99% が段落にそのまま有り、場面の変わり目は 80% が目印と合った
- 道のりを「同じ場面」とみなし、一つの区画に物が12(上限)まで詰まった(海・崖・竹藪・雑木林・落葉・藁屋根の茶店・駄菓子・切り崩した山・梅・西日…)。上限で、帰り道の羽織・板草履が落ちた。いまの形では場所が移れば絵巻が流れるので、「道のりでも、見えている景色の主な物が替わったら new」「物は6つほどまで」と指示した
- 費用は 1,000字あたり $0.163(読み取り Sonnet・描く Opus)。1回(読み取り+描く)の時間は中央値 41 秒・最長 89 秒。描く係は 1回 9〜46 秒・出力 700〜4,700 トークン
