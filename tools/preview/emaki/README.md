# 章の絵巻の試写室 (#51 → #34)

読み進めた話を踏まえて場面を読み取り、余白の絵が話とともに育つ。

- **場面ごとに区画が増える。** 場所が移る・時が飛ぶと、絵巻に新しい区画が足される
- **新しく出た物が描き足される。** 同じ場面のうちは、本文に新しく出てきた物を、いまの区画に描き足す
- 余白には、いまの区画が出る。章の終わりに、その章の区画を順に並べた絵巻が広がり、灯りがともる。次の章では新しい絵巻(持ち越さない)
- 形と画風は #50 と同じ: Claude が書いた形のデータ(SVG の path と色の名前)に、端末の画風を掛ける(`../scene/scene.js`)

判定基準と結果は #51 に書く。

## 見る

リポジトリの一番上で:

```sh
python3 -m http.server 8000
```

http://localhost:8000/tools/preview/emaki/ を開く。いつもの試写室にもリンクがある。

- **1ページずつ:** めくると、本文のページが進む。読み取りの答えは、その回の最後のページの次のめくりで余白に出る
  - 新しい区画は、まず下描き(線だけ)で現れ、次のめくりで色が付く。描き足した物も同じ(「描き足した物は、まず下描きで見せる」で切り替える)
  - 章の最後のページでめくると、章の絵巻が広がる
  - 左の欄に、ここまでの話・いまの場面と物・門で止めたもの・判定役の答えを出す。**ここまでの話と下調べは、本番では画面に出さない**(教えない・不変条件6)
- **全部を並べる:** `?view=all`。版ごとに、章の絵巻と、回ごとの出来事・描いた区画・止めたものを並べる。下調べの有無や、モデルの組み合わせを見比べる

再現用URL:

- `?book=torokko&page=3`(最初の区画が下描きで出た直後)
- `?book=torokko&page=12`(章の最後のページ。めくると絵巻が広がる)
- `?view=all&book=torokko`

## 作る(費用がかかる)

```sh
server/.venv/bin/python tools/preview/emaki/run.py --book torokko                    # 下調べあり・読み取り Sonnet 5.5・描く Opus 5.5
server/.venv/bin/python tools/preview/emaki/run.py --book torokko --no-brief         # 下調べなし(比べる)
server/.venv/bin/python tools/preview/emaki/run.py --book torokko --reader claude-haiku-5-5 --drawer claude-sonnet-5-5
server/.venv/bin/python tools/preview/emaki/run.py --book torokko --start 7           # 7ページ目から読み始める(途中から)
server/.venv/bin/python tools/preview/emaki/run.py --book ginga --chapters 6          # 銀河鉄道の夜の6章まで
server/.venv/bin/python tools/preview/emaki/run.py --unknown                         # 知らない本の下調べだけ
```

- API キーは環境変数 `ANTHROPIC_API_KEY`(無ければ `server/.env` の同じ名前)
- `runs/<本>.<下調べ>.<読み取り>-<描く>[.from<ページ>][.ch<章>].<回>.json` に書き、`runs/index.json` を書き直す
  - 1回呼ぶごとに書く。途中で止まったら、同じ引数でもう一度動かすと続きから
  - 終わった記録は作り直さない(消すと作り直す)
- 読み終えたら、判定役(Opus 5.5)に本の全文と回ごとの中身を渡し、ネタバレが無いかを見させる(`--no-judge` で外す)
- 呼び方は #50 と同じ: 構造化出力(json_schema)・ストリーミング・effort は medium・Opus と Sonnet にはサーバ側のフォールバック。読み取りの system(指示と下調べ)はキャッシュする

## 仕組み

役は4つ。区切り・送るもの・検めは端末の側(`emaki.js`)が決め、`run.py` は Claude を呼んで答えを記録に書くだけ(`device.mjs` で端末の側を呼ぶ)。

| 役 | いつ | 渡すもの | 返すもの | モデル(既定) |
|---|---|---|---|---|
| 下調べ | 本ごとに一度 | 書名と著者 | 知っているか・全体のあらすじ(結末まで)・世界 | Opus |
| 読み取り | 読み終えた本文が 700 字たまるごと・章の終わり | 下調べ・ここまでの話・いまの場面と物・新しく読んだ段落 | 出来事・場面(2つまで)・新しく出た物・変わった物。どれにも本文の語句を付ける | Sonnet |
| 描く | 新しい区画か、描き足す物があるとき | ここまでの話・場面・物の一覧(いまの絵) | 地と、物ごとの形 | Opus |
| 章のまとめ | 章の終わり | この章の出来事 | 200字のまとめ | 読み取りと同じ |

本ごとに端末に残すもの(本番では記録層・`chrome.storage.local`):

- 下調べ(画面に出さず、エクスポートにも入れない)
- ここまでの話: 途中から読み始めたときの前のあらすじ(`seed`)・済んだ章のまとめ・この章の出来事
- いまの章の絵巻(章が終わったら捨てる)

### ネタバレの守り

下調べで先を知っている読み取り係から、描く係と画面へ、先のことが漏れないようにする。

1. **門(端末・機械で):** 出来事・場所・時刻・天気・雰囲気・物の一つずつに、本文の語句を付けさせる。端末が今回送った段落にそのまま有るかを確かめ、無いものは捨てる。止めた語句がまだ読んでいない所にだけ有れば「先の語句」として数える(`whereIs`)
2. **描く係は書名も下調べも知らない:** 渡すのは、ここまでの話と、門を通った場面と物だけ(`drawRequest`)。返った形は、頼んだ物の id のものだけを受け取る
3. **章のまとめは下調べなしで書く:** 渡すのは、門を通った出来事だけ
4. **指示:** 読み取り係には、先のことは言い換えやほのめかしも書かない・雰囲気も先取りしない、と指示する
5. **判定役(試写室だけ):** 読み終えたあと、全文を知る判定役が、回ごとに端末に残っていたものを見る

残る穴(判定役で見る): 門を通った語句に付けた説明(出来事の文・物の見た目)に先のことを混ぜる、どれを主役にするかの選び方、途中から読み始めたときの `seed`(語句で確かめられない)。

### 絵

- 区画は 320×240(#50 と同じ)。物ごとに形を持ち、新しく描いた物は最初のめくりで線だけ(鉛筆の色)、次のめくりから色
- 灯り(`light`)は、読んでいる間は淡い色を置くだけで、章の終わりの絵巻で輪を付けてともす
- 章の絵巻は、区画を順に横へ並べた1枚の SVG(`scrollSvg`)。試写室では左から右へゆっくり流す(区画ごとに 2.2 秒。reduced-motion では流さず、横にスクロールできるだけ)

## 見本を作って分かったこと

`runs/torokko.sample.json` は、Claude Code が同じ決まりで手で書いた読み取りと絵(トロッコ全文・6回・7区画)。道具を確かめるためのもので、計測していないので判定には使わない。

- 2ページごとに読み取ると、その間に場面が二つ過ぎることがある(トロッコの「一人で走る帰り道」と「村」)。読み取りの答えの最後の場面だけを描くと、話でいちばん大事な場面が抜ける。そこで、1回に場面を2つまで返させる(三つ以上なら、いちばん大事な場面と最後の場面)
- 1回目の答えに、前の場面から続けて見える物を id で書かせると、まだ id の付いていない物を指せない。物は名前で指す(1つの区画の中で名前は重ならない)
