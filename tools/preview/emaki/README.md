# 章の絵巻の試写室 (#51 → #34)

読み進めた話を踏まえて場面を読み取り、余白の絵が、読んだ話を演じる。

- **場面が移ると、絵巻が流れて次の区画へ進む。** 場所が移る・時が飛ぶと、横に並んだ区画の帯が流れる(旅をしているように)
- **同じ場面のうちは、物語が動く。** 物が所から所へ動く(トロッコが坂を上り下りする)・新しく出た物が現れる・去る・灯りがともる・日が暮れる
- **演じるのは、読み終えた所の出来事。** 答えが届いた次のめくりから、読んだページを1ページずつ追いかける(この先は演じない)
- **動くのはめくった瞬間だけ(0.9 秒)。** 読んでいる間は止まっている(style.md §0)。一度に演じることが多いときは、めくり1回の中で二段まで続ける(1.8 秒まで。#42 のめくりの演出が残るのと同じ長さ)
- 章の終わりに、その章の区画を順に並べた絵巻が広がり、灯りがともる。次の章では新しい絵巻(持ち越さない)
- 形と画風は #50 と同じ: Claude が書いた形のデータ(SVG の path と色の名前)に、端末の画風を掛ける(`../scene/scene.js`)

真っ白な紙に色が付いていく見せ方(#50 の段階・前の版の下描き → 色)はやめた(2026-10-26 本人: 「真っ白に色がつくというより、その絵の物語が少しずつ動く方が好き」)。

判定基準と結果は #51 に書く。

```sh
server/.venv/bin/python tools/preview/emaki/run.py --book torokko                    # 下調べあり・読み取り Sonnet 5.5・描く Opus 5.5

server/.venv/bin/python tools/preview/emaki/run.py --unknown                         # 知らない本の下調べだけ
```

- API キーは環境変数 `ANTHROPIC_API_KEY`(無ければ `server/.env` の同じ名前)
- `runs/<本>.<下調べ>.<読み取り>-<描く>[.from<ページ>][.ch<章>].<回>.json` に書き、`runs/index.json` を書き直す
  - 1回呼ぶごとに書く。途中で止まったら、同じ引数でもう一度動かすと続きから
  - 終わった記録は作り直さない(消すと作り直す)
  - 記録には形の版(`format`)を書く。前の形の記録は続きから回さない
- 読み終えたら、判定役(Opus 5.5)に本の全文と回ごとの中身を渡し、ネタバレが無いかを見させる(`--no-judge` で外す)
- 呼び方は #50 と同じ: 構造化出力(json_schema)・ストリーミング・effort は medium・Opus と Sonnet にはサーバ側のフォールバック。読み取りの system(指示と下調べ)はキャッシュする

## 仕組み

役は4つ。区切り・送るもの・検め・演じる順は端末の側(`emaki.js`)が決め、`run.py` は Claude を呼んで答えを記録に書くだけ(`device.mjs` で端末の側を呼ぶ)。

| 役 | いつ | 渡すもの | 返すもの | モデル(既定) |
|---|---|---|---|---|
| 下調べ | 本ごとに一度 | 書名と著者 | 知っているか・全体のあらすじ(結末まで)・世界 | Opus |
| 読み取り | 読み終えた本文が 700 字たまるごと・章の終わり | 下調べ・ここまでの話・いまの場面と物と所・新しく読んだ段落 | 出来事・場面(2つまで)・新しく出た物・形の変わった物・同じ場面での動き。どれにも本文の語句を付ける | Sonnet |
| 描く(演出) | 新しい区画か、描き足す物があるとき | ここまでの話・場面・物の一覧・この回の出来事(描き足しのときは、いまの絵と所) | 地・所(spots)・物ごとの形と足もと(at)・居る所・灯り・出来事に沿った動き(beats) | Opus |
| 章のまとめ | 章の終わり | この章の出来事 | 200字のまとめ | 読み取りと同じ |

- **所(spots):** 描く係が区画ごとに決める、物が居られる所・動いて行ける所(坂の上・茶店の前・画面の外の左など)。座標と、その所での大きさ(奥は小さく)を持つ
- **動き:** `move`(所へ)・`leave`(去る)・`light`(灯る)・`dark`(消える)。ほかに、新しく出た物が「現れる」、同じ場面で時刻が移ると「日が暮れる」(色を重ねる)
  - 新しい区画の動きは描く係が、この回の出来事の番号を付けて返す
  - 同じ場面の続きの動きは読み取りが、本文の語句を付けて返す

本ごとに端末に残すもの(本番では記録層・`chrome.storage.local`):

- 下調べ(画面に出さず、エクスポートにも入れない)
- ここまでの話: 途中から読み始めたときの前のあらすじ(`seed`)・済んだ章のまとめ・この章の出来事
- いまの章の絵巻: 区画ごとに、地・所・物(形・足もと・いま居る所・灯り)。章が終わったら捨てる

### ネタバレの守り

下調べで先を知っている読み取り係から、描く係と画面へ、先のことが漏れないようにする。

1. **門(端末・機械で):** 出来事・場所・時刻・天気・雰囲気・物・動きの一つずつに、本文の語句を付けさせる。端末が今回送った段落にそのまま有るかを確かめ、無いものは捨てる。止めた語句がまだ読んでいない所にだけ有れば「先の語句」として数える(`whereIs`)
2. **描く係は書名も下調べも知らない:** 渡すのは、ここまでの話と、門を通った場面と物と出来事だけ(`drawRequest`)。返った形は、頼んだ物の id のものだけを受け取る。動きは、門を通った出来事の番号が付いたものだけ
3. **章のまとめは下調べなしで書く:** 渡すのは、門を通った出来事だけ
4. **指示:** 読み取り係には、先のことは言い換えやほのめかしも書かない・雰囲気も先取りしない、と指示する
5. **判定役(試写室だけ):** 読み終えたあと、全文を知る判定役が、回ごとに端末に残っていたものを見る

残る穴(判定役で見る): 門を通った語句に付けた説明(出来事の文・物の見た目)に先のことを混ぜる、どれを主役にするかの選び方、途中から読み始めたときの `seed`(語句で確かめられない)。

### 演じる順(`timeline`・`stageAt`)

- 回 [a, b] の答えは、b の次のめくりから、その回のページ数ぶんのめくりで演じる(読んでいるページを1回分遅れて追いかけ、遅れはたまらない)
- 語句の有るページごとに一まとまりにする。新しい区画はそれだけで一まとまりにし、その中の動きは次のまとまりに回す(現れる前の様子を見せてから動かす)
- まとまりは、めくり1回に一つ。足りなければ、めくり1回の中で二段まで続ける(0.9 秒ずつ)。それでも余れば最後の段にまとめる
- 章の最後の回の答えは、余白では演じず、章の終わりの絵巻に入る

### 絵

- **区画:** 320×240(#50 と同じ)。余白では、区画を横に並べた帯を流して、いまの区画を見せる。区画の両端は紙に溶かす
- **層:** 区画の中は、地(`groundSvg`)・物ごとの層(`thingSvg`・透明)・時刻の色を重ねる層。いちばん上に、縁を揺らしながら紙に溶かす覆い(`edgeSvg`)を置く
- **動き:** 物の層を CSS の transform(所へ動かす・大きさ)と opacity(現れる・去る・灯りの入れ替え)で 0.9 秒かけて移す。どれも描き終えた画像を動かすだけなので、めくりのたびに水彩のフィルタを掛け直さない
- **灯り:** 灯っていない物は淡い色を置くだけ。灯ると光の輪が付く。章の終わりの絵巻では全部ともす
- **章の絵巻:** 区画を順に横へ並べた1枚の SVG(`scrollSvg`。物は最後に居た所)。左から右へゆっくり流す(区画ごとに 2.2 秒。reduced-motion では流さず、横にスクロールできるだけ)
- reduced-motion では、余白も動かさずに置き換える

## 見本を作って分かったこと

`runs/torokko.sample.json` は、Claude Code が同じ決まりで手で書いた読み取りと絵(トロッコ全文・6回・8区画・動き10)。道具を確かめるためのもので、計測していないので判定には使わない。

- 2ページごとに読み取ると、その間に場面が二つ過ぎることがある(トロッコの「一人で走る帰り道」と「村」)。読み取りの答えの最後の場面だけを描くと、話でいちばん大事な場面が抜ける。そこで、1回に場面を2つまで返させる(三つ以上なら、いちばん大事な場面と最後の場面)
- 物は名前で指す(1回目の答えの中では、まだ id の付いていない物を指せない。1つの区画の中で名前は重ならない)
- 区画が現れるのと同じめくりで物が動くと、動く前の様子が見えない。区画を一まとまりにして、動きは次のまとまりに回した
- 2ページの間に「区画が二つと、それぞれの中の動き」があると、めくり1回に一つでは足りず、遅れがたまる。めくり1回の中で二段まで演じることにした

## 本人が回した前の形の版から分かったこと

`runs/torokko.old-format.json` は、本人の API キーで、前の形(描き足すだけで物が動かない)のまま回したトロッコ(2026-10-26。6回の読み取りと描くまで。章のまとめと判定役の前で止まった)。判定には入れない。

- 読み取りの語句は 99% が段落にそのまま有り、場面の変わり目は 80% が目印と合った
- 道のりを「同じ場面」とみなし、一つの区画に物が12(上限)まで詰まった(海・崖・竹藪・雑木林・落葉・藁屋根の茶店・駄菓子・切り崩した山・梅・西日…)。上限で、帰り道の羽織・板草履が落ちた。いまの形では場所が移れば絵巻が流れるので、「道のりでも、見えている景色の主な物が替わったら new」「物は6つほどまで」と指示した
- 費用は 1,000字あたり $0.163(読み取り Sonnet・描く Opus)。1回(読み取り+描く)の時間は中央値 41 秒・最長 89 秒。描く係は 1回 9〜46 秒・出力 700〜4,700 トークン
